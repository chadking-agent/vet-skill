# Gemini cross-model review — vet-skill v1.2.0

Unstated Assumptions & Contract ViolationsContract Violation (Cache Integrity/Safety): When loading from cache, the code checks cached.get("static") == static, but does not verify whether the cached findings or score match the cached verdict securely, nor does it re-evaluate _verdict_from(). If an attacker manipulates the local cache JSON file to store a PASS verdict alongside high/critical static findings, the cached entry is replayed directly without validation against current gating logic.Contract Violation (LLM Unreachable with --with-llm): Contract 1 states: "with --with-llm, an unreachable LLM endpoint must produce HOLD (never auto-PASS)". However, the code sets bridge_ok = False if the LLM fails, and _verdict_from correctly returns HOLD when not bridge_ok. But look at cached_hit validation: if a previous run stored a successful LLM review (bridge_ok=True), and on a subsequent run with --with-llm the endpoint is unreachable, the cache entry matches, bridge_ok is loaded as True, and the tool may return a cached PASS based on stale LLM results rather than failing-safe when the bridge is currently down.Edge Cases Not Handled & Failure Modes Under Unexpected InputArchive Extraction Bomb / Zip Slip Vulnerability: In _maybe_extract, the code checks tar members for absolute paths, .., and symlinks/hardlinks, but completely skips these checks for zip files (zipfile.ZipFile(target).extractall(out)). A malicious zip file containing absolute paths or path traversal sequences (../../) will write files outside of workdir, risking arbitrary file overwrite on the host system.Unbounded Memory via _bundle_for_llm: The LLM bundling function reads files line-by-line or head-first (_read_head(path, 8000)), but it aggregates them into an unbounded list parts and joins them before applying the character slice limit (bundle[:MAX_BUNDLE_CHARS]). If a skill directory contains thousands of small files, parts will contain thousands of strings, creating a massive memory footprint prior to truncation.Infinite Recursion / Symlink Loops in rglob: The scanner uses target.rglob("*") without checking for symlinks (followlinks=False is not set by default in Path.rglob across all Python versions or can follow directory symlinks). A malicious skill containing a cyclic symlink directory structure will cause an infinite loop or RecursionError / exhaustion of MAX_SCAN_FILES.Hidden CouplingSchema Version vs. Cache Structure Coupling: SCHEMA_VERSION is incremented when the code changes, but the cache key only hashes configuration parameters (BRIDGE_URL, BRIDGE_MODELS, LLM_API_KEY, SCHEMA_VERSION). If the static RULES regex patterns change while SCHEMA_VERSION remains unchanged or if the script logic changes without updating the version, old cache files containing outdated static findings structures will be incorrectly trusted for new rule sets.
